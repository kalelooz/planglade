# PlanGlade 0.2.0

This is PlanGlade's first versioned public self-host preview.

## Upgrade path

There is no supported upgrade from an earlier public release because `0.2.0`
establishes the first public database and storage baseline. Start with empty
persistent volumes. Do not reuse databases from private prototypes or local
development snapshots.

## Migrations

The release applies `20260808020000_initial_public_schema` through the one-shot
Compose `migrate` service. The backend starts only after that service exits
successfully. The automated release rehearsal applies the checked-in migration
SQL to a fresh SQLite database, creates sentinel workspace data, backs up both
data stores, mutates them, restores them, and checks SQLite integrity. CI also
runs `prisma migrate deploy` against a separate fresh database.

## Configuration

Run `npm run setup:local` to generate ignored local secrets. Local
email/password authentication and local attachment storage are the defaults;
OAuth, Firebase, and outbound email are optional. Review `.env.example` and
[the self-hosting guide](../../backend/docs/SELF_HOSTING.md) before exposure.

## Backup and restore

There is no pre-upgrade dataset for this first baseline. After adding data,
back up both `planglade_data` and `planglade_attachments` from the same stopped
state and complete a restore drill before relying on those backups. Follow the
[backup and restore runbook](../../backend/docs/BACKUP_RESTORE.md).

## Rollback

For a failed first installation, preserve logs, stop the stack without `-v`,
and correct configuration or host requirements before retrying. Once real data
exists, rollback requires restoring compatible database and attachment backups
together; replacing only the application source is not a data rollback.

## Known limitations

This remains an early self-host preview. TLS termination, automated backups,
monitoring, malware scanning, and horizontal multi-backend coordination are not
bundled. Review the self-hosting guide before public exposure.
